# Storage, the TypeScript build, tests

Detailed notes, moved out of CLAUDE.md. A `public/js/x.js` path means the source `client/x.ts`; a page's "inline script" is `client/pages/<page>.ts`.

A real-time, multiplayer, round-robin writing **game** for Byler (Will Byers × Mike Wheeler) fanfiction. Players join a session by a 4-letter code, vote on a scenario prompt, then take turns adding one line each to a shared story under a per-turn countdown. It is deliberately **static-prompt / no-AI / no-build-step** — a single Node process serving static pages over Socket.IO. Persistence is one layer, `src/storage.js`: every document (the user store, game snapshots, solo docs, the content pack, the writers' reference) is a `kind/name` JSON blob. Without `DATABASE_URL` (local dev, tests) the blobs are the JSON files under `data/`, `saves/`, `content/`, `writers-reference/`; with it (Replit's built-in Postgres) **the database is the store** — loaded into memory at boot, read from the cache, written as ordered upserts, disk never touched. First boot seeds every kind from disk once (users/saves/docs from a migrating deploy, content/reference from the repo); after that the database wins and `npm run reseed-content` is how a repo pack edit reaches production. `server.js` calls `storage.init()` before importing anything that reads (`site.js` included). Designed to be uploaded to Replit and run with the Run button.

- **"Saved" means the store took it** (after a writer lost words, 2026-09-21). In Postgres mode reads come from memory and the upsert is queued, so a write the database refused used to be logged and forgotten — the words then lived only in the process, and the next restart rolled the story back. Now: (1) a queued job writes the row **as the cache holds it when the job RUNS** (`syncRow`; put and del are the same job), and a second write to a row whose job hasn't started shares that job (`waiting`) — so nothing older can land after something newer, and two quick saves are one upsert; (2) a failed job is **retried until it lands**, backing off through `COWRITE_STORAGE_RETRY_MS` (default `250,1000,4000,15000,60000`, the last one repeating; tests shrink it), tracked in `storage.unlanded` (`kind/name` keys, shown by `/api/admin/storage` beside `lastError`); the original promise still rejects for a caller that awaits it; (3) `pool.on("error")` logs a dropped idle connection instead of letting the emit kill the process; (4) `storage.flush()` makes one immediate attempt at every owed row, and `server.js` handles **SIGTERM/SIGINT**: stop listening, `await storage.flush()`, exit — an 8s timer is the floor under a database that never answers. `writeDoc()` keeps the put's promise in a WeakMap and `docLanded(doc)` hands it out; **`PUT /api/docs/:id` awaits it and answers 503 `{unlanded: true, rev}`** when the store refused (no `doc` in the body, so the editor can't paint itself clean). `rev` there is what a re-read gives — moved in the memory-first store, unmoved on plain files — and the editor adopts it so its retry isn't a conflict with itself, writes the local draft, and stays Unsaved. Tests: `test/storage.test.mjs` (retry carries the newest copy, flush, pool error, coalesced upserts), `test/docs.test.mjs` (the 503 and the retry, by making the docs dir read-only), `test/shutdown.test.mjs` (`ctx.term()` in helpers.mjs sends SIGTERM and returns the exit code + output).

**The client is migrating to TypeScript on the `migration` branch** (`docs/FRONTEND_ASSESSMENT.md` is the why): `client/` is the TypeScript source tree mirroring `public/js/` — `client/status.ts` emits `public/js/status.js` — and `scripts/build.mjs` strips the types with esbuild (no bundling, no minify by default, `--minify` for a deploy) and stamps a `// GENERATED …` banner on every emitted file. **The emitted `.js` is NOT committed** — `public/js/` is gitignored and `prestart`/`pretest` emit it, so `esbuild` is a runtime `dependency` (a Replit deploy that skipped devDependencies would otherwise never boot; `.replit`'s `[deployment]` also runs `npm run build` explicitly) and the server's imports of `public/js/shared/*` only exist after a build; edit the `.ts`, never the `.js`. `tsconfig.json` uses `rootDirs: ["client", "public/js"]` so a `.ts` can import a not-yet-converted `./util.js` neighbour and type-check. `test/build.test.mjs` fails if an emitted twin is stale, if a file under `public/js` has no `client/` source, or if `tsc` finds an error. **Every module under `public/js` is converted** (67 `.ts` sources in `client/`, emitted file-for-file; `castle-trees.ts` is the 154 KB SVG blob and stays untouched). Shared contracts live in `client/shared/` (`brands.ts` branded strings, `wire.ts` the socket/REST shapes, `themes.ts` the theme registry the SERVER imports as `public/js/shared/themes.js`, `reactions.ts` likewise as `public/js/shared/reactions.js`), and `client/components/gimmick-types.ts` is the `Gimmick`/`GimmickMountOpts` base every toy extends. `client/globals.d.ts` declares `window.gsap`. `tsconfig.json` maps the pages' root-absolute `/js/*` imports (inbox-panel, inbox-page) onto `client/` first, then `public/js`. **esbuild's emit differs cosmetically from hand-written JS** — emoji stay UTF-8 (`charset: "utf8"` in the build), but `60000` prints as `6e4` and an `export const` may become a trailing `export { … }` list — so a test that regexes an EMITTED file's source must accept those spellings (`test/pages.test.mjs`, `test/gimmicks.test.mjs`, `test/inbox.test.mjs` do). **The pages' inline scripts are modules too**: `client/pages/<page>.ts` → `public/js/pages/<page>.js`, loaded by `<script type="module" src="/js/pages/<page>.js">` (every page; only the tiny GSAP entrance/hero scripts stay inline). A page module reads the site name with `siteName()` — a static module never passes through `renderPage()`, so a `{{SITE_NAME}}` token in it would ship raw. The Socket.IO event maps are `ServerToClient`/`ClientToServer` in `client/shared/wire.ts` (game, gimmicks, inbox nudge, the solo editor's `doc-*`); every socket page and `SocketLike` (gimmick-types.ts) is typed with them, so add a line there when `src/game.js` gains an event. A test that regexes a page's SCRIPT reads `public/js/pages/<page>.js` (`test/pages.test.mjs`'s `page()` appends it for `/write`). **The server is checked against the same contracts** (`tsconfig.server.json`: `checkJs` over `server.js`, `src/`, `lib/` — `noImplicitAny` off, catch variables `any`, otherwise strict): `io` is `Server<ClientToServer, ServerToClient>` (JSDoc in server.js and `createGame`), so every `socket.on`, every `emit` and every ack in `src/game.js` is checked against `wire.ts` — an event, a payload field or an ack shape the contract doesn't describe fails `npm run typecheck` and `test/build.test.mjs`. The JSDoc typedefs live where the shape lives: `User`/`InboxMsg`/`Store` in `src/store.js`, `Writer`/`StoryLine`/`Session` in `src/game.js` (the lazily-created gimmick maps are optional `any`s). A handler reads its payload through `loose(p)` (a `Record<string, any>`) and validates the fields itself — the wire type says what a well-behaved client sends, the server trusts none of it. When `game.js` gains an event, add it to `wire.ts` FIRST; the server check tells you the moment the two disagree.

The test suite (`test/`) uses Node's built-in `node:test` + `socket.io-client` (devDependency). `test/helpers.mjs` boots one isolated server per test file (random port, temp `COWRITE_DATA_DIR`/`COWRITE_SAVE_DIR` — those env vars override the `data/` and `saves/` paths) and provides `api`/`conn`/`emit` helpers plus `signup`/`startedGame` fixtures. Files: `auth.test.mjs` (accounts, validation messages, reset cycle), `game.test.mjs` (rounds, badges, sanitization, pause, timeout-commit), `reclaim.test.mjs` (rejoin, account reclaim, gating, cooldown, restart-rehydration), `archive.test.mjs` (privacy, dashboard, presence), `admin.test.mjs` (moderation powers, each paired with a "a normal account can't" assertion). Keep tests hermetic — never point them at the real `data/`/`saves/`. `COWRITE_UNFURL=stub` is set by the helper so chat link previews (`src/unfurl.js`) never fetch anything; `=0` turns them off entirely. For ad-hoc debugging you can still drive a running server with a throwaway Socket.IO script; kill stale servers first: `lsof -ti:3000 | xargs kill -9`.
