# Game: sessions, turns, seats, chat, export

Detailed notes, moved out of CLAUDE.md. A `public/js/x.js` path means the source `client/x.ts`; a page's "inline script" is `client/pages/<page>.ts`.

The backend is `server.js` + `src/` + `lib/`; the frontend is `public/` (six pages + shared ES modules + CSS). Everything else (`.replit`, `README.md`, `package*.json`, `.gitignore`) is scaffolding. Tests live in `test/` (see Commands).

- **`server.js`** — a ~35-line entry point; the backend lives in `src/`: `sanitize.js` (trust-boundary sanitizers + palette), `passwords.js` (scrypt), `store.js` (JSON user store + public shapes + startup badge migration), `game.js` (`createGame(io)`: sessions map, saves/ persistence, every socket handler, archive/dashboard read helpers), and `routes.js` (`registerRoutes(app, game)`: every HTTP API route) — plus pure rules in `lib/` (`achievements.js`, `streak.js`). Live game state is **in-memory** in the sessions `Map` (`code -> session`), snapshotted to disk (see below). Each socket tracks one `joinedCode` via `socket.data`.
- **`public/*.html`** — a multi-page frontend, no framework, no bundler (see `docs/REFACTOR_PLAN.md`): `index.html` (homepage: hero + login/signup, bounces signed-in visitors to the dashboard), `dashboard.html` (`/dashboard` — profile, presence, live games, quick start), `game.html` (`/game` — ALL live play; entry via `?code=` join, `?new=1` create, else the localStorage rejoin blob; the URL carries the game code), `archive.html` (`/archive`, `?code=` deep-links a story), plus `reset.html`. Express serves the clean URLs. Shared markup (background layers, topbar, theme switch, nav drawer) is injected by `js/chrome.js`. CSS lives in `public/css/base.css`; client logic in native ES modules under `public/js/` — kernel (`util.js`, `api.js`, `socket-client.js`, `sounds.js`, `auth-guard.js`, `status.js`, `theme.js`, `nav.js`, `export.js`), view builders (`dashboard-view.js`, `archive-view.js`), and `components/` (`editor.js` cleanHtml, `story-feed.js`, `chat-view.js`, `countdown.js`, `auth-forms.js`). Client unit tests run on node:test with jsdom (`test/dom.mjs`). Inside `game.html`, play is phase-driven: card `<div>`s (`waiting` → `choosing` → `game` → `over`) show/hide via `onlyShow()`, plus a `gameMsgCard` for join/pending/error states.
- **`content/prompts.json`** — the curated scenario bank, read once at startup.

### The session lifecycle (the core mental model)

A session moves through **phases**, held in `session.phase`, and the server broadcasts state on every transition:

```
waiting  →  choosing  →  writing  →  over
(lobby)     (group vote)  (round-robin)  (reveal)
```

- **waiting**: writers gather; only the host sees start controls (seconds-per-turn, rounds).
- **choosing**: `start-game` seeds `session.options` via `fillOptions()` — see **Prompt modes** below. **Voting is APPROVAL voting**: `s.votes` is socket id → `Set` of options, `vote {prompt, on?}` TOGGLES one scenario on the caller's ballot (`on` forces a direction; the ack carries `on` + the whole ballot) and `tally()` counts every tick; anyone can append a custom scenario (`add-prompt`). **Nothing finalizes on its own**: each writer marks `ready {ready}` (`s.ready`, socket ids; refused outside choosing) and `finalize-vote` (host-only) is refused with "Not everyone is ready yet." until `allReady(s, hostId)` — every CONNECTED non-host seat is ready (ghosts never block, the host's own click speaks for the host). `game-state` carries `voted` (seats with ≥1 tick), `ballots` (socket id → option indices — public, like the tally), `ready` (ids) and `allReady`. A new deal (`shuffle-options`, a knob change, a mode switch that restores nothing) clears votes AND ready; a single `reroll-option`/`remove-prompt` drops only that option's votes (`forgetOption`) and leaves ready alone; a mode switch's `stashOptions`/`restoreOptions` carries ballots per mode and clears ready. Ballot and ready follow a seat through `seatSocket()`. Client (game.html): `myVotes` is a Set repainted from `ballots[myId]` on every broadcast, `.option.mine`/`aria-pressed` per tick, the `.ready-row` (`#readyBtn` toggle, hidden for the host; `#readyList` chips 👑 host / ✓ ready / voting…) and `#finalizeBtn` "Start the game →" disabled until `allReady`. `test/vote.test.mjs`; `finishVote(ctx, host, others, prompt)` in `test/helpers.mjs` is how every other test gets a game to writing.
- **writing**: round-robin. `startTurn()` sets a `deadline` and a server-side `setTimeout` that fires exactly at the deadline (`timeUp()`), committing the writer's last live-typing content (`session.lastTyping`) as their line and advancing. Turn order is `session.turnOrder` (array of socket ids); `session.currentIdx` points at the active writer. `submit-line` (or the timeout) calls `advance()`, which appends to `session.story` and moves to the next writer.
- **over**: `endGame()` emits the full story for export.

### Two authority rules that everything depends on

1. **The server owns the clock.** `session.deadline` is authoritative; clients only render a countdown from it. When it's their turn, the client auto-submits at the deadline as a best effort, but the server advances at exactly 0 regardless — using the last relayed `typing` content as the line (the RAW text, `session.lastTypingRaw` — `advance()` sanitizes exactly once; committing the sanitized copy would double-escape quotes) — so AFK/throttled/disconnected writers never stall the game. **Pause/resume** works by stashing `session.remaining = deadline - now`, clearing the timer, and on resume recomputing `deadline` and rearming — see `pause-game` / `resume-game` (host-only, and `startTurn()` always resets `paused`). Every pause (host pause, host-left auto-pause, ghost-turn auto-pause, save-rehydration) also arms `armIdleEnd()`: a writing game left paused for 30 minutes (`COWRITE_IDLE_END_MS` overrides — the tests shrink it) ends itself with a reveal + a system chat line; resuming or a new turn disarms it, and the snapshot stays continuable from the archive.
2. **The server is the sanitization trust boundary.** Story lines and live-typing are **rich text** (a tiny HTML subset) rendered into other players' DOM via `innerHTML`. `sanitizeRich()` escapes everything, then re-enables inline formatting (`<b><i><u><s><strong><em><del>`), blocks (`<h1><h2><h3><p><blockquote><br><hr>`), lists (`<ul><ol><li>`), the closed font-size ladder (`<span class="fs-N">`), and exactly two alignment classes (`<p/h1-3/blockquote class="al-c|al-r">`) — i.e. sanitizeDoc's list MINUS `<a>` and `<img>`, the only entries that carry a url, so a story line can be shaped but never carries a link or loads a remote image; no other attribute ever survives — so `<script>`, `<img onerror>`, and any attribute-bearing tag become inert escaped text. **Never render user-supplied line/typing HTML on the client without it having passed through `sanitizeRich()` server-side.** The client's `cleanHtml()` (walks the `contenteditable` producing the same minimal subset — block elements map to h1-h3/p with `al-c`/`al-r` from text-align styles/attrs, DIV→p) is convenience only, not a security control. The toolbar drives `document.execCommand` (formatBlock / justify* / insertHorizontalRule); story lines render in `<div class="story-line">` wrappers because block html can't nest inside `<p>`. Names, chat, and custom prompts are plain text and always `esc()`'d.

### Client ↔ server event contract

The two files are coupled by Socket.IO event names — changing one side requires the other. Key events:

- Client→server: `create-session`, `join-session`, `start-game`, `vote`, `add-prompt`, `shuffle-options`, `reroll-option {index}` (host-only: redeal ONE option in the set mode, keep the rest, drop votes on it — the ↻ on each card), `finalize-vote`, `submit-line`, `typing`, `pause-game`, `resume-game`, `end-game`, `chat`.
- Server→client: `roster` (waiting room), `game-state` (the main state broadcast for choosing+writing), `live-typing` (relayed in-progress line from the current writer), `game-over`, `chat`, `chat-history`.

`broadcastGame()` is the single source of the `game-state` payload — add any new field a client needs there.

- **Refresh/rejoin**: disconnects don't remove a writer immediately — `markDisconnected()` keeps the seat as a reclaimable "ghost" for `GHOST_MS` (90s), then `removeWriter()` runs. Each writer gets a `token` (returned by create/join acks); the client stores `{code, token}` in localStorage (`cowriteRejoin`) and emits `rejoin-session` on every socket `connect`, and the server swaps the new socket id into `writers`, `turnOrder`, `votes`, and `hostId`. **A reconnect is a NEW socket id, and the client must take it**: game.html's `myId` (what every "my turn" / "am I host" / ballot / ready check compares against) is set from the seat ack — `enterSession` on first entry and `reconnectAck` on every later `connect` (a transient drop: ping timeout after ~45s of silence, sleep, a backgrounded tab, a proxy closing an idle websocket) — and `adoptSeat()` on every `roster`/`game-state` falls back to the writer wearing my `userId`, so a reseat that reaches the page by broadcast alone (a host approving a returning seat) is adopted too. The old silent `() => {}` ack left `myId` stale, which read exactly like being kicked (no editor, no host bar, the host's own auto-pause unresumable) until a hard refresh; `reconnectAck` also surfaces the failures it hid — `Seat expired.`/game gone → `clearRejoin()` + dashboard, `pending` → a waiting note — and `socket.on("disconnect")` shows "Reconnecting…" until the seat is back. `requireAuth` clears the token only on 401/403, never on a network blip. The server logs every disconnect, seat expiry, reclaim (old → new id) and gated re-entry as `[game CODE] …` lines. The rules are pure in `public/js/components/seat-identity.js` (`reconnectOutcome`, `adoptSeatId`) so `test/client-seat-identity.test.mjs` pins the client half; `test/reclaim.test.mjs` drops a transport with `B.io.engine.close()` to pin the server's. Vote auto-finalize and the `total` count use `connectedCount()` so ghosts never block a vote. **Account-based reclaim**: seats also store `userId` for signed-in players, and both `join-session` and `rejoin-session` fall back to matching the `auth` account token against seat `userId`s (shared `seatSocket()`/`gateOrSeat()`), so a signed-in player who lost their localStorage token re-enters a running (or save-rehydrated) game from any device by logging in and entering the game code. **Everyone is an account**: guest play was removed — `create-session` AND `join-session` refuse sockets without a valid `auth` token, so every seat has a userId/username and the account IS the identity (the localStorage seat token is just a fast path). Hosts likewise (snapshotted as `hostName`/`hostUserId`; host handoff prefers signed-in writers; `game-state` carries `hostName` and the client shows 👑 in the session bar and archive). **Gated late-join**: a brand-new writer entering a started game's code becomes a `session.pending` request — the host gets `join-request` popups and answers via `approve-join` (approved writers slot in at the end of `turnOrder`; requesters see pending/denied states; disconnecting cancels the request). **Continued games gate everyone**: `loadSession()` sets `session.gated`, and `gateOrSeat()` turns any un-`approved` returning seat into a pending request while a host is connected — except the true host (`hostToken`), who always enters directly; each seat is approved once (`writer.approved`), after which refreshes are frictionless. Session identity uses `socket.data.joinedCode` (not a closure) so the host's approval can seat another socket. **Spectators**: `spectate-session {code}` joins the broadcast room with NO seat and no auth (read-only by construction — every action handler keys off `joinedCode`, which spectators never get); the homepage lists running stories via public `GET /api/live` (names/counts only) with Watch → `/game?spectate=CODE`. **One chat for the whole table**: `chat {text, name?}` is open to seated writers AND spectators and every line (system `announce()` calls included) goes to the session room, so a watcher follows the whole conversation; `chat-history` replays `s.chat` (snapshotted) to writers and spectators alike. **Links in chat** (2026-09-26): the text stays plain and `esc()`'d, but the client's `linkifyText()` (`client/util.ts`, used by `chatMessageHtml` for person lines only) turns every http(s) URL into `<a class="chat-link" target=_blank rel="noopener noreferrer nofollow">` — `URL_RE` plus a trailing-punctuation trim, so "see https://x/y." links `https://x/y`; `javascript:`, `ftp:` and bare `www.` never link. **Link previews**: the `chat` handler finds the first link with the same rule (`firstUrl()` in `src/game.js`; `test/unfurl.test.mjs` pins the two regexes equal), emits the line at once, then `src/unfurl.js` fetches the page's Open Graph card (title/description/image/site) and the server sets `msg.preview` on the stored message (so `chat-history` and the snapshot carry it) and emits `chat-preview {mid, preview}`; the client appends `linkPreviewHtml()` under that row (`.chat-preview`, a thumbnail that fails to load removes itself). The unfurler is the ONE place the server fetches a user-typed URL: http(s) only, private/loopback hosts refused by name, by literal and by DNS answer, redirects followed by hand (≤3, each re-checked), 5s timeout, html-only, 512 KB read cap, 1h cache of 200 (negatives too), never awaited and never fatal. `COWRITE_UNFURL=0` turns previews off; `=stub` answers a canned card with no network (what `test/helpers.mjs` sets). Tests: `test/unfurl.test.mjs`, `test/client-util.test.mjs` (linkify), `test/client-views.test.mjs` (card markup), `test/game.test.mjs` (the preview round trip). A writer's message carries their seat identity; a spectator's carries their client-minted name (`public/js/spectator-names.js`: Stranger Things name + number in localStorage, `cowriteSpecName`), stripped/length-limited server-side with a palette color by name hash, and `spec: true` (the dock marks it 👁). The docked panel is one log, no tabs. **No session cap**: any number of stories may run at once (the old `COWRITE_MAX_ACTIVE` limit is gone). The true host — or any admin — can `DELETE /api/games/:code` — live players get `game-deleted`, the snapshot is unlinked, the code dies.
- **Codes are permanent**: `saveSnapshot()` runs on create, join, start, every committed line, rename, pause, game-over, and before any seat removal, so `saves/<CODE>.json` always exists and any code can be revived via `loadSession()` (waiting/choosing saves revive as a waiting room; writing/over as themselves). `makeCode()` also checks the saves dir so codes are never reused. **Host controls are a MODAL** (`#hostModal` in game.html, `.host-modal`/`.host-modal-card` in base.css — the `.confirm-modal` overlay shape with a taller scrolling card): the `.doc-side-tab` (`#hostOpen` — a Font Awesome gear over a "Host settings" label set sideways via `writing-mode: vertical-rl`, shown only to the host — game.html `prepend`s it into the gimmick dock's `#gkTabs` after mounting, so it stands at the top of the LEFT-edge stack with the gimmick tabs, `.gk-tabs .doc-side-tab` in base.css making it in-flow and mirrored; both tab kinds are `min-width: 0` with `1em` of padding either side, an icon's width of air around the icon) opens it, the ✕ in the card's corner (`#hostClose`), Escape or a backdrop click closes it (`openHostModal`/`closeHostModal`; losing the host role closes it too), and under 860px the card is the WHOLE screen — full width and height, no radius. Nothing is remembered between opens. `.game-cols` is therefore two columns — story, then who's here + chat — with no drawer column and no `--doc-side-w` (the solo editor's comments rail keeps `components/side-drawer.js` to itself now); the prompt banner lives INSIDE `.game-main`. The session bar also carries the two host actions that act on the GAME rather than the story — **Pause/Resume and End game & reveal** (`#hostGame`, `.sess-acts`) — because those are the ones you reach for mid-turn; they follow the same host condition as `#hostPanel`, which keeps only the settings (rules form, cover) inside the modal. Sessions have a host-settable `name` (`rename-session`, host-only, stripped/40 chars) — and **every session is born named**: `create-session` sets `randomTitle(TITLE_BANK)` (`lib/titles.js`, pure, ≤`MAX_TITLE` = 40 chars cut on a word; the bank is `content/titles.json`'s patterns + word lists, part of the fandom pack, "Untitled" without one; `test/titles.test.mjs`) so nothing is ever listed as a bare code carried in `game-state`, `roster` (which also carries `code`), snapshots, and the archive endpoints; the client shows a session bar (name + ✎ for host + click-to-copy code) on every phase card. **The host can hand the game over**: host-only `make-host {id}` (any connected seated writer; admins too) moves the acting role AND the original-host rights (`hostToken`/`hostUserId`/`hostName`) for good, announces it in chat, snapshots and re-broadcasts; the old host is an ordinary writer after. Client: `seatMenuHtml()` in game.html puts a `.seat-menu` (the dashboard card's `.mg-menu` shape, styled in base.css) with a ⋯ button and "👑 Make host" on every OTHER connected seat in the lobby roster and the players row, only when I am host; one document-level click handler opens/closes and emits. Host role passes to a connected writer while the host is away, but `session.hostToken` remembers the true host: they reclaim the role on rejoin, and the transfer only becomes permanent if their ghost expires (`removeWriter()` updates `hostToken`).
- **Mid-game rule changes**: host-only `update-rules` sets a new `turnSeconds` (applies IMMEDIATELY — the current turn's clock restarts at the new full length, the writer keeps their typed text; a paused game just updates `remaining`) and/or `addRounds`, which extends `maxTurns` (or gives an endless game a finish line). Because this re-broadcasts `game-state` mid-turn, `renderWriting()` tracks a `turnKey` and only clears the editor/live-preview on a real turn change.
- **Save & continue**: `saveSnapshot()` writes the session (story, chat, writer name/color/token seats, rules, remaining time) to `saves/<CODE>.json` (gitignored) on every pause, game-over, and everyone-left auto-pause. `loadSession()` lazily rehydrates a saved code on `rejoin-session` after a restart: seats come back as unclaimed ghosts keyed `ghost:<token>`, the game wakes up paused, and the first reclaimer becomes host. `startTurn()` skips disconnected seats (auto-pausing + snapshotting if nobody is connected), and `resume-game` defers to `startTurn()` when the paused turn belongs to a ghost. After a reveal, `continue-writing` (new turnSeconds/rounds — prompt and story kept, turn order rebuilt from connected writers) is allowed by **`mayContinue()`**: the same authority that may end a game (acting host, admin), the ORIGINAL host by account (`hostUserId`, now carried on `game-state` and `roster`), or — when no connected seat holds the host role — any seated writer; whoever continues becomes acting host, and `continue-writing` SNAPSHOTS at once (the archive reads snapshots, so a continued story must not stay listed as over); a second continue finds the phase already `writing` and is refused; a contributor arriving by code while it runs is a normal gated join. The reveal card mirrors that rule client-side (`canCont` in `updateHostView`) so the Continue button is live for whoever the server would accept, never a story ended by an acting host that nobody in the room can continue.
- **Host handoff**: `removeWriter()` reassigns `hostId` to the next *connected* writer on host departure, and carefully fixes `currentIdx`/`turnOrder` when a writer leaves mid-writing (restarting the turn if the leaver was current). This function is where most turn-order edge cases live.

- **WSQK, the shared radio** (`client/components/wsqk.ts`, rules in `client/shared/radio.ts`, handlers in `src/game.js` next to `set-cover`): the host pastes a YouTube playlist link (the lobby field `#stationInput` or the host modal's `#stationInput2`, `radio-set`; `""` = off air) and everyone at the table — spectators too — hears it from `#radioCard`, a `.side-sec` that `placeChat()` keeps right under the chat in every phase. **The server owns the station** (`s.radio`: playlist, `index`/`videoId`/`title`, `playing`, `positionMs` at `updatedAt`), broadcast as `radio-state` (`broadcastRadio`, with the server's `now` for skew) on every change and replayed by `joinAsWriter()`/`spectate-session` like chat history; it rides the snapshot and a revived game wakes with its station paused (`reviveRadio`). **Only the host's player conducts**: it reports a new track with `radio-track` (a same-index report is a re-anchor, taken only past `REANCHOR_DRIFT_MS` and outside `REANCHOR_COOLDOWN_MS`), and its ⏯/⏭ send `radio-play`/`radio-pause` (a skip is a local `nextVideo()`; the report follows). Every other player walks the playlist by itself and, on each `radio-state`, jumps if on the wrong index or seeks only past `SEEK_TOLERANCE_MS` — nobody else ever emits. The playlist's name comes from the chat's unfurler (`og:title` of the playlist page; `COWRITE_UNFURL=stub` in tests). **Listener state is local** (`cowriteRadio`: volume, mute, folded, off) and never on a socket; **off destroys the player** (no decode cost), mute only silences it. Autoplay: play is tried as saved, then muted with a "tap to listen" nudge, then a "▶ Tune in" button when even that is refused. **Traps**: the iframe renders into `#radioHost` at the foot of `<body>` and never inside the card — placeChat moves the card and a moved iframe reloads mid-song; `#radioHost` is two pixels and `opacity: .01`, never `display: none` (the API stalls); phones (`detectPhone`: coarse pointer under 760px) never get a player — they see the station and a link to the playlist on YouTube. - **Share / Download ▾ is the one export control** (`client/components/export-menu.ts`: `exportMenuHtml(prefix)`, `mountExportMenu(root, {prefix, source})`, `placeMenu` pure): the reveal card mounts it into `#overExport` (prefix `over`) and the archive into `#archExport` (prefix `arch`) — a flyout of Copy (formatted) · Download .html · Download .pdf under one switch, **Sign every line** (localStorage `cowriteExportBylines`). Signed means `signLine()` in `export.ts` opens each line with `<b>name:</b> ` INSIDE its first block (a blockquote's first `<p>`, a list's first `<li>`) so a centred line stays centred and a heading a heading — bold, never a colour, so it survives AO3 and a paste into Docs/Word; a `<hr>` is never signed; plain text reads `name: words`. `buildExports(prompt, story, doc, {bylines})` is the html/plain builder, `client/export-pdf.ts` (`storyToPdf`, `pdfLine`, `loadJsPdf` from the CDN on demand, `printFallback`) draws the PDF with the name as a bold run on the words' own baseline (a signed list item keeps its bullet ahead of the name). The menu opens where it can be SEEN: `placeMenu` flips it above the button (`.up`) when the viewport ends before the list does and hangs it off the right edge (`.right`) when the side runs out; `max-width: calc(100vw - 32px)`.
