# Admins, the content pack, announcements, Discord

Detailed notes, moved out of CLAUDE.md. A `public/js/x.js` path means the source `client/x.ts`; a page's "inline script" is `client/pages/<page>.ts`.

- **Admins** are a fixed list of emails (`ADMIN_EMAILS` in `src/store.js`, read from the `ADMIN_EMAILS` environment variable — comma-separated; a Replit Secret in production, `.env` locally, `TEST_ADMIN_EMAILS` in the suite; unset means no admins. The addresses never live in the repo). The flag is applied at startup, at signup, and at every login, and `isAdmin(u)` reads it; nothing in a request payload can grant it, and `/api/account/email` refuses to claim a listed address. Powers, each enforced server-side next to the normal owner check: join any game without the host gate (`join-session`/`gateOrSeat`), `end-game` in any game they're seated in, `edit-line`/`delete-line`/`rename-session` on anyone's story, `GET`/`DELETE /api/games/:code` plus tags on any snapshot, and **`DELETE /api/docs/:id` on anyone's solo write** (the author gets a `system` inbox note naming the admin, like `deleteGame`'s; profile and `/api/stories?user=` rows carry `deletable` = mine or admin, and `soloRowHtml` shows Delete beside Read/🔒 for an admin, never Continue). Admin-only routes: `GET /api/admin/users` (every account + `lastSeen`), `DELETE /api/admin/users/:username` (refuses admins), `GET /api/admin/games` (every live session), `POST /api/admin/games/:code/end` (end a game from outside it — the reveal fires, the snapshot stays continuable), and **the prompt library editor**: `GET /api/admin/prompts` returns the whole `content/prompts.json` document and `PUT /api/admin/prompts {data}` replaces it — `setPromptData()` in src/game.js validates the lot (non-empty curated `prompts` of strings + `validateIntermediateData`) and only then writes the pack file and swaps the in-memory `PROMPT_DATA`/`PROMPT_BANK`/`INTERMEDIATE`, so the next ballot (and `/api/prompt-options`, which reads `getPromptData()`) deals from it with no restart. The UI is the "Prompt library" section of `/admin`: `promptEditorHtml(doc)` in admin-view.js draws one `<details>` per pool (`PROMPT_POOLS` — the Simple-mode scenarios and `characters` as one-per-line textareas, every axis / the trope bank / each explicit pool as a table of Label · Weight · [Group | Age | Role] · Rules-as-JSON rows, plus the trope groups as `id = Name` lines), `promptRowHtml` adds a row, `readPromptEditor(root, base)` reads it all back into a document (existing rows keep their id, new ones get `slugId(label)`, `text` = label lowercased, a rules cell that isn't a JSON object is an error) and Save PUTs it whole. `test/helpers.mjs` copies `content/` into a temp `COWRITE_CONTENT_DIR` per server so an editor test can never touch the real pack. Pack files are read with `readContent()`/written with `writeContent()` (src/content.js → `storage`), so in production the edit is a `content/prompts` row and survives deploys; the repo's copy reaches production only via `npm run reseed-content`. `lastSeen` is stamped by `touchSeen()` on signup/login/`/api/me` and is what "inactive" is judged on. The UI is `public/admin.html` (`/admin`) with rows from `public/js/admin-view.js`; the nav entrance is revealed by `setUserChip()` for admins and is cosmetic only. **Ask the admin**: the dashboard's help card (`#helpCard`, shown only to non-admins) posts `POST /api/help {text}` — stripped, 2–1000 chars, one every 30s per account — which drops a `help` inbox message from the asker into EVERY admin's inbox. `POST /api/inbox/reply {id,text}` answers any message in your own inbox with a `note` back to its sender (and marks the original read); that's how the admin replies, and it's the Reply button on any inbox message that came from a person. The composer is inline: `replyBoxHtml()` folds a hidden textarea into every person-sent row (`inboxMsgHtml`), Reply unfolds it, Escape closes and Ctrl/Cmd+Enter sends.

**`content/` is the fandom pack** — `site.json`, `prompts.json`, `achievements.json`, `quotes.json` (`docs/CONTENT_PACK.md` is the step-by-step for making a pack for another fandom), resolved by `src/content.js` (`contentPath()`); `COWRITE_CONTENT_DIR` points at an alternate pack, like `COWRITE_REF_DIR` does for `writers-reference/`. `test/content.test.mjs` pins the default and the override. **The app's name is data**: `src/site.js` loads `site.json` (`SITE` = fandom/name/tagline/blurb, generic "Cowrite" fallbacks; **`name` is DERIVED as `<fandom> Cowrite`** — Byler Cowrite, Heated Rivalry Cowrite — unless the pack sets one, so a fandom pack changes one field) — and **the hero writes `{{FANDOM}}` / "Cowrite" fitted to its stage**: `fitHeroWords()` in index.html measures each `<text>` with `getComputedTextLength()` after the fonts land and scales a line wider than 840 of the 900 viewBox units down (never up, floor 36px), so a long fandom name fits without touching the animation and `server.js` serves every page through `renderPage()` — `{{SITE_NAME}}`/`{{FANDOM}}`/`{{TAGLINE}}`/`{{BLURB}}` tokens in the HTML are filled and a `<meta name="site-name">` is injected — registered BEFORE `express.static` so `/index.html` can't leak a raw copy. Client modules never hard-code the name: `siteName()` in `public/js/util.js` reads the meta (chrome.js, export.js, dashboard-view.js); server strings use `SITE.name`. Never write "Byler Cowrite" into a page or module again — use the token or `siteName()`. `test/pages.test.mjs` checks the rendered pages carry no raw token. To edit the scenario bank, change `content/prompts.json`: the root `prompts` array is the curated pool (one scenario string per entry) and the `intermediate` object beside it is the guided-mode library (seasons, canon, places, situations, relationships, tones, the grouped trope bank, the explicit layer) — no code change needed either way. `test/prompt-gen.test.mjs` validates that library (unique slug ids, named trope groups, an adult season, the explicit level marked adultOnly), so a broken edit fails the suite instead of the game. Badge names/thresholds/triggers/descriptions live the same way in `content/achievements.json` — and **the catalogue is live**: `lib/achievements.js` exports `let` bindings recomputed by `applyCatalogue(cfg)`, and `/admin`'s **Badges** section (`badgeEditorHtml`/`badgeRowHtml`/`readBadgeEditor`/`badgeId`/`BADGE_POOLS` in admin-view.js: ranks as id · badge · words · description; secret and open usage badges as id · badge · triggers (comma-separated) · combos (one per line, words joined with `+`) · description; one Save) PUTs the whole document to `PUT /api/admin/achievements {data}` (`GET` returns it), where `setAchievements()` validates (`validateAchievements`: slug ids unique across all three lists, a rank at 0 words, integer `min`, a trigger or combo per usage badge), writes the pack via `writeContent` (a Postgres row on Replit) and swaps it in — a new badge is awarded on the very next committed line, a new rank on the next word count, no restart. Ids are permanent once saved (they sit in every account's `badges`). `GET /api/achievements` sends an ADMIN the recipe — `desc` + `triggers`/`combos` on every usage badge, plus `admin: true` — so `/ranks` shows an admin how each badge is earned (`recipe` on `usageBadgeHtml`, the `.rk-recipe` line); everyone else still gets names only for secret badges. Tests: `test/achievements.test.mjs`, `test/admin.test.mjs` (the live-award proof), `test/client-admin-view.test.mjs`, `test/client-ranks-view.test.mjs`.

- **The writers' reference is editable from /admin** ("Writers' reference" section): `src/reference.js` keeps the bundle mutable (`getReference()`, not a const) and `setReferenceGroup(slug, [{key, words}])` validates one group (snake_case keys via `KEY_RE`, trimmed/deduped words, an emptied category is DROPPED, a group can't be saved empty), rewrites that group's data file (honouring the manifest's `root` wrapper), reloads the bundle for the next palette open; reads and writes go through `storage` (kind `reference`, name = manifest path minus `./`/`.json`, `index` included), same rule as the prompt library. Routes: `GET /api/admin/reference` (the bundle) and `PUT /api/admin/reference/:slug {categories}`; UI builders `refEditorHtml`/`refGroupHtml`/`refCategoryHtml`/`readRefGroup`/`refKey` in admin-view.js — one `<details>` per group, one textarea per category (a word per line), an add-category row, and a Save per GROUP since each is its own file. `test/helpers.mjs` copies `writers-reference/` into a temp `COWRITE_REF_DIR` per server so a test never edits the real bank. Tests: `test/admin.test.mjs`, `test/client-admin-view.test.mjs`.
- **Email check from /admin** ("Email (SMTP)" section, ✉ Check email setup → `GET /api/admin/smtp`, admin-only): `smtpStatus()` in routes.js reports which `SMTP_*` vars are set (booleans, never values) and, with a host configured, runs `transport.verify()` and returns the REAL error + code — because `/api/send-reset` deliberately answers a generic 502 "try again later" when `sendResetEmail` throws (the token is rolled back), logging the reason only to the console. The transport (`smtpTransport()`) is rebuilt from the env per call with 10s connect/greeting and 20s socket timeouts, so a blocked port fails fast instead of hanging the request.
- **Content backup from /admin**: the "Content backup" section's ⬇ Download content button fetches `GET /api/admin/content.zip` (admin; bearer header, so the page fetches it and saves the blob itself) — every `content/*` and `reference/*` document AS THE STORE HOLDS IT (the database in production, so it captures /admin edits the repo doesn't have), zipped in the repo's own layout (`content/<name>.json`, `writers-reference/<name>.json`) so a download can be dropped over the repo and `npm run reseed-content`-ed back. `src/zip.js` is a dependency-free deflate zip writer (`buildZip([{name, data}])`, `node:zlib`'s `crc32`). Tests: `test/zip.test.mjs` (round-trips through the system `unzip`), `test/admin.test.mjs`.

- **Announcements are the admins' blog** (`/announcements`, `public/announcements.html` + pure builders in `public/js/announcements-view.js`, nav-drawer entry `📣 Announcements`, `src/announcements.js` for the store): ONE storage document, `announcements/announcements` (`data/announcements.json` locally, a Postgres row on Replit — `SINGLE` in storage.js lists the single-document kinds, users and this), holding `{posts}` newest-first, each `{id, title, html, at, byId, byName}`. A post is RICH TEXT written in the shared WYSIWYG (`toolbarHtml("ann")` + `mountRichToolbar(…, {idPrefix: "ann"})` over `#annEditor`, sent as `cleanHtml(el, {doc: true, urls: false})`) and sanitized with `sanitizeRich()` — the story-line subset, which is exactly what that toolbar offers — and its **title is derived, never typed**: `titleOf(html)` takes the first `h1–h3`'s text, else the opening words cut on a word at 120 with an ellipsis. The page injects `post.html` as-is (server-sanitized, like a story line) and the head row is just date · author (+ Delete). Routes: `GET /api/announcements` (auth; `{posts, admin}`), `POST /api/admin/announcements {html}` and `DELETE /api/admin/announcements/:id` (`requireAdmin`). The composer and the Delete button exist ONLY in an admin's markup (`postListHtml(posts, {admin})`, `composerHtml()`, mounted when the payload's `admin` is true) — the page agreeing with the server, not the enforcement. Tests: `test/announcements.test.mjs` (each admin power paired with a normal-account refusal), `test/client-announcements-view.test.mjs`.

- **Announcements are MARKDOWN** (`markdown` on the post is the source of truth, rendered by `lib/markdown.js` — a dependency-free renderer emitting only the story-line subset, raw html escaped — then `sanitizeRich()`'d into `html`, what the page injects). The composer is a plain textarea; `POST /api/admin/announcements {markdown}`. **Admins edit in place**: `PUT /api/admin/announcements/:id {markdown}` → `updatePost()` re-renders/re-sanitizes under the same id and `at`, stamps `editedAt`/`editedBy` (every reader sees an "edited" tag); `postHtml(post, {admin})` adds an Edit button and `editorHtml(post)` — a folded `.ann-editbox` holding the post's markdown with Save/Cancel — admin markup only.
- **Discord** (`src/discord.js`, no gateway, no library): slash commands arrive as Ed25519-signed POSTs at `/discord/interactions` (`verifyInteraction` over `req.rawBody`, kept by `express.json`'s `verify`; `handleInteraction` is pure — `/cowrite-link`, `/cowrite-online`; PING→PONG), outbound posts use the bot token (`postToChannel`): `POST /api/admin/announcements/:id/discord` sends the post's markdown verbatim to `DISCORD_ANNOUNCE_CHANNEL_ID` (the per-post "Post to Discord" button, admin markup only), `POST /api/games/:code/discord` (host/admin; `#discordShareBtn` in the invite section) posts the code with Join/Spectate link buttons to `DISCORD_GAMES_CHANNEL_ID`. `npm run discord-register` PUTs `COMMANDS`. Env: `DISCORD_PUBLIC_KEY/APP_ID/BOT_TOKEN`, the two channel ids, `COWRITE_ROLE_ID` (`withRole()` prefixes `<@&id>` to every post and sets `allowed_mentions` to that role alone, so nothing in a title or the markdown can ping anyone else), `PUBLIC_APP_URL` for links; `GET /api/admin/discord` reports which are set. Tests: `test/discord.test.mjs`, `test/markdown.test.mjs`.
