# Dashboard, homepage, chrome and CSS rules

Detailed notes, moved out of CLAUDE.md. A `public/js/x.js` path means the source `client/x.ts`; a page's "inline script" is `client/pages/<page>.ts`.

- **Dashboard** (signed-in lobby): `GET /api/dashboard` (auth) returns `onlineUsers` (from `onlineSockets`, fed by the client's `identify` event on connect/login/logout) and `liveGames` (non-over sessions with players/host/phase); the dashboard page polls every 10s (plus `/api/users` for the writers directory) and Join buttons route to `/game?code=…`. **Live games are lit**: every `.live-game` row (`liveGameInfoHtml`) carries a `.lg-rail` with an `.lg-bulb` of `--accent-2` running down it, an `.lg-aura` that swells as it passes, a crossing `.lg-sheen` and a pulsing `.lg-pip` on the online count, staggered per row by `--lg-i`, waking on hover (lift, glow, Join fills in) — every colour a theme token (a test refuses hard-coded ones); `liveGames` rows carry `paused`. **Deny cooldown**: a denied join request stores a 5-minute retry-after in `session.denied` keyed by account id — both the new-writer and gated-reclaim request paths check it.

- **The dashboard's first card is the whole of "how am I doing"** — one stat row of three counts of the same kind (words, badges, the streak ring), the rank bar spanning underneath them (it is a progress bar, not a count, so it doesn't compete for a column), then the recent-achievement chips. They used to be split between the welcome card and a rail card, which asked you to look in two places for one answer.

- **The column under the profile is two tabs** (`#dashTabs`, `.dash-tab-btn` rows, choice in localStorage `cowriteDashTab`): **Dashboard** is MINE — recent achievements, games in progress, solo writes, previous games (`#tabDashboard`); **Community** is EVERYONE — the Announcements section (`#annSec`: the newest post as `#annCard`, whose tendril border is mounted only when the panel first shows, since a hidden card measures 0; NO heading over it and no older rows — the card's own tag says "Announcement", and `#annMore` holds only the empty-state line; a "See all announcements" link to the page), all live games (`#dashLive`), the writers directory and the help box (`#tabCommunity`). The Community tab wears the writer count (`#tabCommunityN`) and a count dot (`#tabCommunityDot`) for announcements newer than the browser last saw (localStorage `cowriteAnnSeen`, stamped when the tab is open). The profile card above the tabs keeps only the stats and rank bar. `.dash-tab > .card` flattens the same way `.dash-col > .card` does. `test/pages.test.mjs` pins which id sits in which panel.
- **The dashboard's rail is navigation, and it stands on the LEFT** (grid placement in dashboard.css — `grid-template-columns: 280px minmax(0, 1fr)`, `.dash-rail { grid-column: 1 }` — with the column FIRST in the DOM, so a phone reads your games before the nav) (`.dash-nav`/`.dnav` in dashboard.css, static markup in dashboard.html `#railNav`): Inbox (wearing the unread count, `#navInbox`) · **👥 Cowrite ▸** (New game `/game?new=1`, Join game — opens `#joinModal`, Your previous games `/archive`, All previous games `/stories?kind=game`) · **✒️ Solo writes ▸** (Your solo writes `/writes`, New solo write) · **👤 Account ▸** (Profile, Settings) · AO3 skin previewer (the ONLY glowing row, with its `.dnav-new` pill) · Admin (`#railAdmin`, `class="dnav hidden"` + `data-admin`, revealed by the page for `me.admin`) · Other games (`/games`, "soon" tag) · Invite a friend (a plain last row: its "Link copied ✓" feedback would vanish inside an auto-closing menu). **The ▸ rows are side-flyouts** — `client/components/nav-flyout.ts` (`FlyoutItem`/`FlyoutGroup` types, `flyoutItemHtml`/`flyoutGroupHtml`/`navFlyoutHtml` builders, `mountNavFlyout(root, {onAction, admin, hoverOpen, phoneQuery})`): a parent is `button.dnav.dnav-parent[aria-haspopup=menu]` over a `.dnav-sub[role=menu]` panel of `.dnav[role=menuitem]` items (`href` → `<a>`, `action` → `<button data-action>`, reported to `onAction`); on desktop the panel is `position: fixed` beside the row (placed from its rect, clamped to the viewport, re-placed on scroll/resize), under 900px it folds in-flow under the row (`.is-fold`); one open at a time; click toggles, Enter/Space/ArrowRight/Down open on the first item, ArrowUp on the last, arrows cycle, ArrowLeft/Escape close and refocus the row, outside click closes; hover opens after 120ms on `(hover: hover) and (pointer: fine)` only and a hover-opened panel closes on leave while a click-opened one stays; GSAP entrance when loaded, close clears `clearProps: "transform,opacity,visibility,height"` (never `all`), CSS keyframe fallback (`dnav-sub-in`, finite). The page's hand-written rail must equal `navFlyoutHtml(DASH_RAIL)` — `test/client-nav-flyout.test.mjs` compares them and drives the wiring on jsdom. Emoji are plain text in `.dnav-ico`, which base.css gradients directly. **Join is a modal** (`#joinModal`, `.confirm-modal > .confirm-card.join-card` with a `.confirm-x` ✕ — a reusable corner dismiss in base.css): the `#code` field (focused on open, Enter joins) + `#joinBtn`, `#lobbyErr`, and `#joinLive` = `joinLiveRowsHtml(lastLive, me)` (dashboard-view.ts) — the games running now from the SAME `/api/dashboard` poll the Community tab reads (`lastLive` cached in dashboard.ts, repainted while the modal is open), each with a `data-join` Join button. `.dnav` is `display:flex`, so `.dnav.hidden`/`.dnav-sub.hidden`/`.dnav-wrap.hidden` twins exist (the `.hidden` source-order rule); `test/dashboard.test.mjs` pins the ids, order, the twins and that no flyout animation is infinite. `GET /api/stories?kind=game|write` narrows the library to one shelf (anything else = both; `/stories` retitles itself for `kind=game`).

- **Writers is a full-width card; Friends is a rail card** (`.friends-card`, between the nav and the quote): the directory with its search box spans the main column, and the people you already know sit under the navigation where a glance finds them.

- **The streak explains itself**: `streakMetaHtml(streak, best)` (dashboard-view.ts) is the one builder for the line beside the ring on the dashboard AND the profile, and it carries a `?` button (`.streak-help`, `aria-label` "How streaks work") whose `data-tip` is `STREAK_TIP` — one game line a UTC day, a missed day restarts at 1, solo writes don't count. Change `lib/streak.js` and that sentence together. The shared tooltip (`client/tooltip.ts`) now opens on keyboard focus as well as hover, for every `[data-tip]`.
- **The writers directory filters in the browser**: under `#writerSearch` sit `#writerWho` (Everyone / Friends / Not friends yet), `#writerWords` (the `WORD_BANDS` in dashboard-view.ts) and `#writerRank`, with a live `#writerCount`. `filterWriters(rows, {q, words, who, rank})` and `writerRanks(rows)` are pure and pinned in `test/client-page-views.test.mjs`; `/api/users` already ships `badge`, `wordCount` and `friend`, so nothing changed server-side. The rank list is the ranks somebody currently holds (lowest first, plus "No rank yet"), rebuilt on every 10s poll by `paintRankOptions()`, which keeps the chosen rank if anyone still holds it. Your own row is neither a friend nor a stranger; a pending request counts as not friends yet.
- **The writers directory shows where you stand with each writer, not their badge**: `GET /api/users` rows carry `me`/`friend`/`requested` for the caller and `friendStateHtml(u)` renders a `friend` or `requested` chip or an **Add friend** button (`POST /api/friends/request`, the row flips to `requested`); nothing on your own row. **The rank bar is words over the next rank's cost** (`badgeProgress`: `wordCount / nextBadge.min`, capped at 99 until earned — the old "banked = words − to-go" sat at 1% until halfway). The dashboard carries no welcome line.

- **The dashboard shows no messages** — a message is a conversation and `/inbox` is where conversations happen, so the dashboard carries only the FACT that one is waiting: `loadInbox()` reads `/api/inbox` for its `unread` count and paints the rail's Inbox link badge (`#navInbox`). `mountInbox` is mounted by `/inbox` alone.

- **The newest announcement draws its own border**: `#annCard` is mounted with `components/tendril-border.js` (`mountTendrilBorder(el, {horn})`): a `.vine` SVG behind the content whose rounded frame (`frameD`, `RADIUS` 14 = the card's radius) draws itself clockwise in `DRAW` = 0.95s (GSAP, `/vendor/gsap.min.js` which the dashboard already loads) while the 📣 (`.ann-horn`) flickers on; **once the entrance has played it GLIMMERS**: `glimmer()` loops a `userSpaceOnUse` linearGradient (`--accent-2` → `--ink` → `--accent-2`, read off the card's computed style, re-read on `data-theme` change) sweeping along `.vine-shine` every `SWEEP` + `SWEEP_GAP` seconds while `.vine-glow` flashes with it. The resting stroke is `--accent` (CSS), so every theme paints its own; no vines, no read state. No GSAP / reduced motion → `settle()` (the frame simply appears); a ResizeObserver rebuilds geometry without replaying the entrance; on `visibilitychange` → visible a frozen entrance (background tabs throttle rAF) is finished outright and the glimmer started. Test: `test/client-tendril-border.test.mjs`.

- **The host's ⋯ menu on a dashboard card**: `myGamesFor()` marks each card `hosted` (the ORIGINAL host, `hostUserId`), and only those cards get a "⋯" more-options menu (`.mg-menu`) with **End game & reveal** (`POST /api/games/:code/end` — host or admin; `endGameByCode(code, by)` revives a paused snapshot if it isn't live, names the actor in the chat line, fires the reveal, and the snapshot stays continuable) and **Delete story** (the existing `DELETE /api/games/:code`). Each goes through `confirmDialog()` (`components/confirm-delete.js` — the site's `.confirm-modal` shape as a promise; the inbox's `confirmInboxDelete` is one wording of it), and both are **disabled while the game is active** (`g.live && !g.paused`) with a "Pause the game first" note — you don't end or delete a story out from under people mid-turn. `deleteGame(code, by)` now takes the deleter: besides killing the session (`game-deleted` to live players) and unlinking the snapshot, it drops a `system` inbox note into every OTHER seated account — `🗑 “Title” (CODE) has been deleted by hostname.` — so the story leaving their dashboard is explained. Test: `test/archive.test.mjs`.

- **The homepage is the hero, then a tour** (`public/index.html`; the design is the Claude Design project "Byler Cowrite home page UI", direction 1a "Pinned panels"): after the hero comes a sticky `#tourBar` (brand mark, the eight-dot chapter rail `#tourDots` lit by an IntersectionObserver, a Log in button that opens the auth card), the "Start here" section (`.home-start`: the blurb beside the existing `#lobby` auth card, so every auth id is unchanged), then `#tour` — eight `.tour-panel`s (sticky claim left, screen right) built by **`public/js/tour-screens.js`** (`TOUR`, `tourHtml()`, `tourDotsHtml()`, one `screen*()` builder per chapter: the game, live typing, the solo editor, comment mode, ranks, gimmicks, the dashboard, the themes) — and a closing `.home-close` card. **The screens are the real UI rebuilt as static markup on the theme tokens** (`.ts-*` classes in `public/css/home.css`, never a hard-coded surface colour; only the three PALETTE writer colours), so the tour wears whatever theme the visitor picks; the themes screen shows `public/img/themes/<id>.jpg` and marks the one being worn, and clicking a thumb previews it (attribute only). "or take the tour ↓" under Enter (`#heroMore`) exits the hero the way Enter does and scrolls to the tour. The dice image is `public/img/d20.png`. `test/client-tour-screens.test.mjs` pins the chapters, the token-only rule and the page order.
- **Hero landing**: a full-screen `#hero` overlay "writes" the title: SVG `<text>` outlines draw in via stroke-dasharray/dashoffset (dash 460 > any glyph subpath; free-plugin equivalent of DrawSVG), gradient fill fades in (`paint-order: stroke`, gradient stops use theme CSS vars), and an underline `<path>` traces via `getTotalLength()`. Runs after `document.fonts.ready` so strokes match real glyphs; Enter un-writes it and hands off to the lobby entrance (setTimeout safety-hide for throttled tabs); without GSAP the title renders complete and static. The tagline ("If we're both going crazy, we might as well write it down.") types itself out character-by-character (GSAP tween over a counter + blinking caret) and is clickable — it opens `#featuresModal`, a full feature rundown; keep that list in sync when features change. **Never on a touch device while GSAP is loaded** (`featuresAllowed()` in index.html — the modal over the tweening hero crashed mobile browsers; the tagline is plain text there and the tour covers it). The hero lives only on the homepage; signed-in visitors bounce to `/dashboard` before it matters.

- **The nav drawer scrolls itself** (`overflow-y: auto`, bottom padding clearing `--footbar-h` so the last link never hides under the foot bar, which is above it in z), and **Log out is a plain text row pinned to its top** (`.nav-logout`, `position: sticky`, first child of `#navDrawer` — icon + word, no button chrome). **The drawer is site pages only**: Log out · 🏠 Dashboard · 📣 Announcements · 📖 All stories · 🏅 Ranks & unlocks · 🛡️ Admin (`#navAdmin.hidden`, revealed by `setUserChip`) — no separators, no Inbox/Profile/Settings/AO3 rows; everything you DO lives in the dashboard rail's flyouts. `test/client-chrome.test.mjs` pins the exact href list.
- **Foot bar**: theme peek + the tip jar are one thin sticky strip (`FOOT_BAR` in chrome.js, `--footbar-h` in base.css — every bottom-pinned thing, `body` padding included, clears itself by that variable), not two floating chips over the page. Ko-fi's floating widget script is gone: `mountKofi()` now injects a modal holding Ko-fi's own embeddable panel (`KOFI_EMBED`) and only sets the iframe `src` on the first open, so a page view that never asks to tip loads nothing third-party. Peeking keeps the bar (it's the way back) and hides the Support half.

- **Link previews are Open Graph tags injected by `renderPage()`** (`ogTags()` in src/site.js: og:title/site_name = `SITE.name`, description = the blurb, `twitter:card` = `summary_large_image`, the image `public/img/og-banner.png` 1200×630 — built ABSOLUTE on `PUBLIC_APP_URL`, root-relative without it). The banner is captured from the homepage hero in `?og=1` capture mode (`html.og-capture`: buttons, foot bar, tour and caret hidden, the fixed tagline instead of a random quote) by `scripts/og-banner.sh` with the server running; re-run it after a hero or theme change. Discord caches unfurls — test a new banner with a fresh `?v=` on the link. `test/pages.test.mjs` pins the tags and the file.

- **The AO3 skin previewer is its OWN REPOSITORY and its own site** — `ao3-skin-previewer`, a separate git repo deployed at `https://ao3-skin-previewer.replit.app`. This repo holds NONE of it and no longer mounts it: there is no `/ao3-preview` route, no `AO3_PREVIEW_DIR`, no sibling-directory lookup in `server.js`. **The app links OUT to the previewer's own site**, `https://ao3-skin-previewer.replit.app` (`AO3_PREVIEWER_URL` in chrome.js), in three places, each glowing with the accent-2 pulse and opening in a new tab: the homepage tour bar (`.bar-link.bar-link-glow`, home.css), the nav drawer (`a.nav-glow` after Settings, base.css) and the dashboard rail (`a.dnav.dnav-glow` before Invite a friend, the ONLY glowing row now — `#soloBtn` no longer pulses — with a `.dnav-new` "New" pill that pulses with it, dashboard.css); `test/pages.test.mjs` pins all three and that the glows use theme tokens only.
- **The animation budget** (`test/animation-budget.test.mjs`): the dashboard used to blink blank while scrolling on every theme — Chrome scrolls cheaply only while the page's tiles stay valid, and two things invalidated them every frame: infinite CSS animations of `box-shadow`/`top` in the scrolling content (the AO3 glow rows, the live-game bulb and pip, the gathering glow, the cursed chip) and FIXED chrome wearing `backdrop-filter` (user chip, theme toggle, hamburger, foot bar), which re-composites the strip beneath it on every scroll frame, on every page. The rules, pinned by the test: **an infinite animation outside `.bg-set` may animate only `opacity` and `transform`** — a glow is a `::after` pseudo-element carrying the shadow whose opacity breathes; the bulb travels by `translateY` (−140.6%/184.4% of itself = the old −90%/118% of the rail); **the fixed chrome never blurs** — it stands on `--panel-solid` (`color-mix(in srgb, var(--bg-2) 80%, var(--panel))`, derived per theme in `:root`); and **a GSAP loop (`repeat: -1`) lives only in theme.ts (behind the page) or behind `whenVisible()`** (`components/when-visible.ts`: IntersectionObserver + `visibilitychange`, `onShow`/`onHide`, a stop fn) — the announcement border's glimmer and the gathering sparkles pause off screen and in a hidden tab. Popovers, menus, toasts and modals keep their blur: they are transient and sit still.

- **`.hidden` is only as strong as its source order.** `.hidden { display: none }` lives early in `base.css`, so ANY later rule of equal specificity that sets `display:` on a class silently outranks it and the element stays on screen — this is how the stories toolbar (`.chat-row`) and the guided prompt knobs (`.guided-controls`) kept showing while JS believed it had hidden them. The fix is never `!important`: add the class to the grouped `.CLASS.hidden { display: none }` block near the end of the file. `test/client-chrome.test.mjs` now catches the whole family — it reads every `class="… hidden"` in the pages and chrome, and fails if a co-class gets a later `display:` without a matching `.CLASS.hidden`.
- **The dashboard/profile rail breaks below the column under 900px** — and the collapse is re-declared at the END of `dashboard.css`'s editorial block, because that block's two-column `.dash-wrap` rule comes after the first breakpoint and would otherwise outrank it (the `.hidden` source-order trap again; the rail overlapped the column on phones). `test/pages.test.mjs` pins that every two-column `.dash-wrap` rule precedes the last 900px collapse.
- **Fields are 16px on touch devices** (the last rule in base.css, `@media (hover: none) and (pointer: coarse)`): iOS Safari zooms the page in when a smaller field takes focus and the zoom outlives the route, which read as "every page opens zoomed in". Never fix that with `maximum-scale`/`user-scalable=no` — `test/pages.test.mjs` refuses it.
- **A full-width page keeps a 16px edge**: `.wrap > .archive-inner` carries `padding-left/right: 16px` unconditionally (the `.wrap >` guard keeps it off `.archive-drawer`, which is padded already), so /archive, /stories, /admin and /inbox never run flush against the bezel — it costs nothing while the 860px reading column is centred and it is exactly what `.archive-inner.wide` needs once `max-width` gives way to `100%`. The solo write page is the deliberate exception (see below).

- **Both shelves share a layout picker** (`STORY_VIEWS`/`viewToggleHtml` in archive-view.js, choice in localStorage `cowriteStoriesView`): list, or 3/4/6 across. The grid is `auto-fill` with a floor derived from the chosen count, so too many columns degrade to fewer instead of producing slivers, and a multi-column view widens the page (`.archive-inner.wide`) because four covers can't share an 860px reading column. `components/view-picker.js` is the DOM half (`mountViewPicker`/`applyGrid`, choice in localStorage) and `/archive` mounts the same control — its group headings stay outside the grids, so the class lands on a per-group `.arch-group` container rather than the whole list.
