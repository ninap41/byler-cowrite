# Themes, ranks page, fonts and theme artwork

Detailed notes, moved out of CLAUDE.md. A `public/js/x.js` path means the source `client/x.ts`; a page's "inline script" is `client/pages/<page>.ts`.

- **Themes are rank rewards**: `content/achievements.json`'s **`themeUnlocks`** maps a theme id (the registry is `THEMES` in `public/js/theme.js`) to the `wordTiers` id that earns it — hand-editable like the rest of the catalogue. A theme NOT listed is free for everyone, and a theme pointing at a tier that no longer exists falls back to free (`THEME_UNLOCKS` filters at load, so a typo can't lock a theme away forever). **Admins get every theme regardless of rank.** The rules are `tierForTheme`/`canUseTheme`/`unlockedThemes`/`themeLocks` in `lib/achievements.js`; `GET /api/themes` (auth OPTIONAL — signed out returns the locks with an empty `unlocked`) serves `{locks, unlocked, admin}` and `publicUser` carries the same `themes` list so signing in re-gates without a second request. Client-side, `initTheme()` returns a `setGate({locks, unlocked})`: an unearned row stays listed (a reward you can see coming) but wears 🔒, a tooltip naming the tier and its word cost, and refuses the click; `applyTheme()` bounces a locked theme back to `DEFAULT_THEME` (**Upside Down** — `public/js/theme.js`, the `data-theme` attribute on every page and the `:root` token block in base.css all agree), which also covers an unearned theme left in `localStorage` by another account on the same browser. `chrome.js` fetches the gate on mount and re-gates from `setUserChip(user)`. This gate is **cosmetic by nature** — a theme is a CSS attribute on the visitor's own document, so like the admin nav entrance it hides a reward rather than protecting anything. `test/themes.test.mjs` pins every `themeUnlocks` key to a real theme id and every value to a real tier. **A rank-up says what it unlocked**: `rewardsForTiers(newTierIds)` (lib/achievements.js) gathers the themes AND gimmicks the freshly crossed tiers hand out — theme labels come straight from `public/js/theme.js`'s `THEME_LABELS` (the module has no DOM at top level, so the server imports it; one registry, not two), gimmicks derived from the themes those tiers unlock (a gimmick rides its theme — see **Gimmicks** below), named from the `GIMMICKS` registry — and `creditLine()` says it three ways: the chat announcement gains "That unlocks the X theme", the `badge-earned` toast carries `unlocks: {themes, gimmicks}` (each `{id, name}`) plus, on a rank-up, `themes` = the writer's full wearable list so `regateThemes()` (chrome.js) opens the menu on the spot, and a `system` inbox note with the same `unlocks` field lands in the writer's inbox so the reward is findable after the toast fades. `describeRewards()` builds the sentence fragment; a rank that unlocks nothing stays a plain badge announcement.
- **The Ranks & Unlocks page** (`/ranks`, `public/ranks.html` + pure builders in `public/js/ranks-view.js`, nav-drawer entry `🏅 Ranks & unlocks`) shows the whole reward economy DYNAMICALLY: the rank ladder (from `/api/achievements`, whose `wordTiers` now ship `id` so the page can join them), each rung's themes as screenshot cards (theme locks from `/api/themes` — a lock's wire value is `{tier, name, min}`, a bare tier-id string also works so a fandom pack can ship the simpler shape), the gimmick riding each theme (from `/api/gimmicks`' catalogue, whose registry entries in `lib/gimmicks.js` carry an `icon` field), free themes, a per-gimmick rundown, and the word badges (secret usage badges stay mysteries until earned — descriptions come only from the viewer's own `badgeDescs`). Viewable signed OUT (everything locked, a sign-in nudge instead of the progress bar); signed in it marks earned rungs, the current rung, and words-to-next. **Theme screenshots** live at `public/img/themes/<themeId>.jpg` (640×360, captured with headless Chrome on a temp capture page that mounts the chrome and flips `data-theme` + `ui-peek`); a missing image degrades to a swatch card (`.rk-theme.noshot`), so a theme pack without shots still renders. Clicking a thumb previews that theme on the spot (attribute only — not saved, the menu's gate still owns the real choice). `test/client-ranks-view.test.mjs` pins the builders AND that every registry gimmick has an icon and every `THEMES` entry has a screenshot on disk.

**Font Awesome is SELF-HOSTED** (`public/vendor/fontawesome/`: `css/fa.min.css` = Free 6.7.2's `fontawesome` + `solid` + `regular` sheets concatenated, ttf fallbacks stripped, plus the two woff2 files; a `<link rel="stylesheet" href="/vendor/fontawesome/css/fa.min.css" />` just before `/css/base.css` in each `<head>`, cached 7 days like the rest of `/vendor`; `test/pages.test.mjs` pins the link on every route, that no page references the kit CDN, and that the sheet names only fonts we ship — the old kit script fetched a loader, a stylesheet and webfonts from fontawesome.com on every page view). Only free icons in the solid/regular styles are available; adding a brands icon means downloading `brands.min.css` + `fa-brands-400.woff2` the same way, so `<i class="fa-solid fa-…">` icons are available site-wide. **`fonts.json`** (repo root) is the map of theme → font per role (`display`/`body`/`story`/`mono`), mirroring the `--font-*` custom properties in `public/css/base.css` for all 19 themes, plus the six families and the exact Google Fonts CDN link every page's `<head>` carries. There are NO font files in the repo — the families are CDN-loaded. It is documentation-as-data, not a runtime source of truth (the CSS is), so `test/fonts.test.mjs` re-derives it and fails if the two drift: change a `--font-*` value and update `fonts.json` in the same commit. **The font registry is `public/js/fonts.js`** — `LOADED_FONTS` (the CDN families, mirrored by `fonts.json`'s `families`+`extraFamilies`), `SYSTEM_FONTS` (curated local faces, mirrored by its `systemFonts`), `SITE_FONTS` = both — read by the theme menu, by `doc-prefs.js`'s `DOC_FONTS` (`theme` + the registry) and by the test, so no menu can offer a face the others don't know. **The theme menu's Font row** (`#themeFontPick` at the foot of `#themeMenu`, mounted by `initTheme()` as a `components/flip-select.js` menu with `portal: true` — every row set in its own face; while open the list is LIFTED to `<body>` as `.flip-menu.flip-portal`, fixed at the toggle's spot, so it escapes the menu's overflow and scrolls on its own when the list is long, and goes home on close; the theme menu's outside-click check treats a click in that portaled list as inside) is a per-browser override of the theme's BODY, STORY AND DISPLAY (heading) faces (only mono stays the theme's), so a chosen face dresses the whole page: localStorage `cowriteFont` holds the key, every page's head script sets `data-font` on `<html>` before first paint exactly like `data-theme`, `initTheme()` validates it (`cleanSiteFont`, junk → removed) and returns `applyFont`/`font` beside `applyTheme`, and `html[data-font=…]` rules in base.css (right after the last theme block; `html[attr]` outranks every `[data-theme]` token block) do the overriding — `applyTheme()` never touches it. The write page's own `--doc-font` still wins there; "Theme font" in that menu now means "the theme's face as overridden site-wide". `test/fonts.test.mjs` pins registry ⇔ fonts.json ⇔ the `[data-font]` CSS blocks ⇔ `DOC_FONTS` ⇔ every head script. **A GSAP close clears only what the tweens set** (`clearProps: "transform,opacity,visibility"` in both theme.js and flip-select.js — `"all"` also wiped the inline `transition: none`, so every open after the first fought the CSS fold-out and the list looked like it never opened), and closing the theme menu `fontPick.close()`s the portaled list.

- **The Cleradin moon is a photograph in `screen`** (`public/img/moon.webp`, the only raster in a theme otherwise drawn in code): `.moon` itself is the halo gradient, its `::before` lays the photo over that halo with `mix-blend-mode: screen` — the photo's black sky contributes nothing under screen, so there is no cut-out and no matte to maintain and the halo shows through the dark maria — and its `::after` drops the theme's violet back over the disc in `mix-blend-mode: color`, hue only, so the craters keep their own values. Both pseudo-elements carry the same radial mask, which feathers the photo's limb so it never lands as a hard circle. The moon does NOT parallax.
- **Vecna's clock is a grandfather clock** (`public/js/components/vecna-clock.js`, same shape as the tower: `CLOCK` holds the proportions, labelled groups, pure builder). `#vc-case` is the long case as stacked boxes each narrower than the one below with a moulding at every joint (that stepping IS the silhouette), `#vc-glass` is the waist door with the pendulum drawn inside it and CLIPPED by it — so the bob passes out of sight at the extremes the way it does behind a real case — `#vc-dial` the brass face with twelve numerals and the hands. The case reads as ONE object — no vines hanging off it, no pediment perched on top: loose marks around a silhouette make it scenery, and a clock standing plainly in a room it doesn't belong in is the more frightening thing. The pendulum is the only moving part: a CSS rotation on `#vc-pend`, `transform-origin` set to `CLOCK.cx`/`CLOCK.pivotY` so it hinges at the pivot rather than its middle. The old turning `.clockface` dial stays, dimmed, as the sky behind it.
- **The Cleradin tower** (`public/js/components/cleradin-tower.js`) is the theme's centrepiece and is drawn from numbers, not plotted by hand: `TOWER` holds every proportion, `radiusAt()` is the single taper (0 at the foot, 1 under the balcony), and `bow()` — one downward-bowed line across the shaft — is why courses, ledges, steps and rings all read as a cylinder. Everything else composes those: `#cl-shaft` (masonry with staggered joints; there is deliberately NO spiral stair band — the diagonal stripes it drew across the shaft were removed, and the test asserts it stays gone), `#cl-openings` (lancets + a quatrefoil rose), `#cl-door`, `#cl-moss` (placed as a FRACTION of the shaft's width at that height, so a patch can never float off the stone), `#cl-balcony`, `#cl-roof`, `#cl-dormer`, `#cl-spire`. The builder is pure (a string, no DOM) so `chrome.js` inlines it into `.bg-set.cleradin .tower` and a test can read it; every colour is a `--cl-*` custom property set on `.tower` in base.css, so re-skinning the tower is editing CSS, not SVG. The `.tower` element is positioned by `top`/`left`, NOT by a transform — the scroll parallax owns `transform` on it and the two must not fight. It is deliberately **enormous and hard left** (`height: 420vh; left: -14%`): only the roof is in frame at the top of a page and scrolling walks down the stone. Its parallax rate is not authored — `data-par="auto"` tells `startParallax()` to DERIVE it as `(tower height - viewport) / (scrollable page height)`, so the drawing travels exactly once over whatever the page turns out to be (short page: slow; long page: fast; neither runs out of tower), remeasured on resize and by a ResizeObserver on `body` for pages that grow after load. The distant keep keeps a fixed `data-par="0.08"`. The moon is the one thing that does NOT parallax — a woodcut full moon built in four passes (limb-darkened disc, maria, rays, craters + speckle) with `LIGHT` as the single light direction: a crater's lit wall is a dashed circle ROTATED to face it, so every crater on the disc agrees without any being hand-placed.

- **`previewTheme()`** (on the `ThemeController`, beside `applyTheme`) wears a theme for this page view only: `paint(theme, persist=false)` sets `data-theme`, the active button and the backgrounds but never writes `cowriteTheme`, and skips the rank gate — it shows someone else's theme (the author's on a public solo write), not the visitor's own. `setGate()` never steps back from a previewed theme; the next `applyTheme` (a pick in the menu) ends the preview and saves as ever. Pinned in `test/client-chrome.test.mjs`.
